# Бинарный GBD на C: полный просмотр коллизий

Отдельный точный оракул для фиксированного набора координат `S`. Историческое бинарное ядро и его публичный API не меняются. Новый оракул всегда полностью проходит правый список (`d=1`, одна попытка); порога веса и ранней остановки нет. Результат — минимум по ненулевым словам, равным нулю на `S`, а не обязательно по всему коду. Пустое `S` означает поиск по всему коду.

`head[key]` и `next[index]` хранят цепочки индексов Грея (значение 0 — конец цепочки). Вектора не хранятся целиком в списках: правый вектор обновляется XOR одной строки, левая комбинация восстанавливается из маски при проверке. На каждую левую комбинацию добавляется один 32-битный индекс; таблица ключей остаётся плотной. При полноранговой исходной матрице число проверенных ненулевых коллизий равно `2**(k - rank(G_S)) - 1`. Входные строки предполагаются линейно независимыми; обёртка не проверяет ранг.

## Сборка и проверка в Linux/WSL

Из корня репозитория:

```sh
cc -std=c11 -O3 -march=native -Wall -Wextra -fPIC -shared \
  -o /tmp/libqgbd_all_collisions.so min_cw_gbd_q/src/binary_all_collisions/gbd_all_collisions.c
python min_cw_gbd_q/tests/integration/test_binary_all_collisions.py /tmp/libqgbd_all_collisions.so
```

Чтобы сверить прежнюю серию, запустите тот же тест из окружения Sage с аргументом `--baseline min_cw_gbd_q/tests/results/direct_oracles/all-oracles-comparison.json`. Он запускает только новое C-ядро и читает сохранённые минимальные веса; ACM 994 и прямое перечисление не перезапускаются.

В Python-интерфейсе `BinaryAllCollisions(path).search(rows, n, S)` строки и возвращаемое слово упакованы в целые числа, младший бит соответствует столбцу 0. Например, `search([0b101, 0b110], 3, [2])` возвращает слово `0b011` веса 2. Для нулевого подкода `word` и `weight` равны `None`.
